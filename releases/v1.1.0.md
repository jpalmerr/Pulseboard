## Highlights

PulseBoard v1.1.0 adds webhook notifications, authentication middleware, SSRF protection, TLS support, Prometheus metrics, and stale endpoint detection — significantly expanding the library's production readiness without breaking any existing APIs.

---

## New Features

### Status Change Callbacks

Register functions that fire only on status transitions, not every poll cycle.

```go
pulseboard.WithStatusChangeCallback(func(change pulseboard.StatusChange) {
    log.Printf("%s: %s → %s", change.EndpointName, change.PreviousStatus, change.CurrentStatus)
})
```

The `StatusChange` type carries endpoint name, URL, labels, previous and current status, latency, timestamp, and any error. Multiple callbacks are called in registration order with panic recovery.

### Webhook Notifications

Send HTTP POST requests on status transitions via `WebhookNotifier`:

```go
pulseboard.WithStatusChangeCallback(
    pulseboard.WebhookNotifier("https://hooks.slack.com/...",
        pulseboard.WithWebhookEventFilter("down", "degraded"),
        pulseboard.WithWebhookDebounce(30 * time.Second),
        pulseboard.WithWebhookHeaders(map[string]string{"Authorization": "Bearer token"}),
        pulseboard.WithWebhookTimeout(5 * time.Second),
    ),
)
```

Also configurable in YAML via the `webhooks:` block with environment variable expansion for headers.

### HTTP Authentication Middleware

Protect the dashboard with built-in middleware:

```go
// Basic auth
pulseboard.WithMiddleware(pulseboard.BasicAuth(func(u, p string) bool {
    return u == "admin" && p == os.Getenv("DASHBOARD_PASSWORD")
}))

// Bearer token (constant-time comparison)
pulseboard.WithMiddleware(pulseboard.BearerToken("token-a", "token-b"))
```

`WithMiddleware` accepts any `func(http.Handler) http.Handler`. Also configurable in YAML via `auth:`.

### SSRF Protection

Block requests to private networks and restrict polling to known hosts:

```go
pulseboard.WithBlockPrivateNetworks()          // blocks RFC1918, loopback, link-local, cloud metadata
pulseboard.WithAllowedHosts("api.example.com") // allowlist — anything else is rejected
```

Both redirect targets and initial URLs are validated.

### TLS Support

**Server-side HTTPS:**

```go
pulseboard.WithTLS("/path/to/cert.pem", "/path/to/key.pem")
```

**Client-side TLS for polling:**

```go
pulseboard.WithInsecureSkipVerify()                                    // dev/internal only
pulseboard.WithTLSMinVersion(tls.VersionTLS12)
pulseboard.WithClientCert("/path/to/cert.pem", "/path/to/key.pem")    // mTLS
```

All options are available in YAML under `server.tls` and `client.tls`.

### Prometheus Metrics

Expose a `/metrics` endpoint in Prometheus text format:

```go
pulseboard.WithMetrics()
```

Records per-endpoint poll latency histograms, status transition counters, and error rates.

### Stale Endpoint Detection

Mark endpoints as stale when no update is received within a configurable window:

```go
pulseboard.WithStaleThreshold(2 * time.Minute)
```

## Changes

### New `error` status

A new `StatusError` (`"error"`) status distinguishes check mechanism failures — extractor panics, JSON parse errors, regex mismatches, missing fields — from `StatusDown` (service unreachable). The dashboard displays errors in orange with a dedicated filter and count.

### Stricter grid URL template validation

Grid `url_template` values using `{{.key}}` placeholders are now validated against declared dimensions at config load time. Templates referencing undeclared keys or containing unparseable `{{...}}` sequences return an error immediately rather than failing at runtime.

---

## Fixes

- Extractor panics are now correctly classified as `error` rather than `down`
- Dashboard shows a loading spinner before the first poll completes, replacing a blank grid
- Dashboard shows an empty-state message when the active status filter has no matching endpoints
